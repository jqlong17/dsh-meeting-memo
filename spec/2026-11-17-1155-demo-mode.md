# 演示模式：用假数据跑通六个页面，便于对外演示

> **Status**：Accepted
> **起始日期**：2026-11-17
> **预估工时**：120–180 分钟（mock 数据 60 / 路由拦截 40 / 开关与横幅 30 / 测试与验证 30）
> **对应提交**：`ca2caa0`

## 背景 / 问题

现在要给别人演示这个插件，只能拿自己的真实数据：

- 真实转写里有同事姓名、客户名、项目代号，不能随便投屏；
- 真实数据时间不连续（今天只有零星几句），演示时时间轴只有几根柱子，看不出版式；
- 「纪要」「背景」「任务」几个页面经常是空的，演示要临时造几条，造完还得删掉；
- 一旦演示者手滑点了保存/删除，会直接改到真实数据。

这不是「界面不好看」，而是**没法安全地对外演示**。

## 目标与非目标

**目标**

1. 「关于」页增加一个开关：进入 / 退出演示模式。
2. 开启后，「今日」「纪要」「背景」「任务」「转写服务」「说话人识别」六个页面全部显示固定的假数据，与真实文件完全隔离。
3. 假数据要覆盖每个页面的主要内容形态：时间轴有密度、转写带说话人和相似度、纪要有 2 场、背景有 2 张卡、任务有 1 个进行中 + 1 个已完成、转写服务有模型与内存曲线。
4. 演示模式下**任何写操作都不落到真实文件**：保存、删除、生成、开始/取消任务、切换模型全部是空操作或就地更新内存。
5. 顶部常驻一条横幅，明确写着「演示模式 · 当前是示例数据」，并提供退出入口——防止演示完忘了关。
6. 刷新页面后仍保持演示模式（存在浏览器本地），退出后立即恢复真实数据。

**非目标（这次不改）**

- 不动手机端页面（`resources/mobile/` 仍读真实数据）。
- 不动 Agent 工具（`meeting_minutes_*`）返回的数据。
- 不提供「导入/导出演示数据」，假数据写死在代码里。
- 不追求假数据与真实文件结构 100% 一致，只保证面板渲染需要的字段齐全。

## 参考实现（Prior art）

| 参考 | 采用 | 不采用 / 理由 |
| --- | --- | --- |
| Storybook 的 decorators + `msw`（mock service worker） | 「在数据入口处拦截，而不是改每个组件」的思路 | 不引入 msw，我们没有浏览器端 service worker 需求，多一层依赖 |
| Chrome DevTools 的 Request Blocking | 「按 op 名单决定放行还是拦截」的做法 | 不做网络层拦截，直接包一层 RPC 函数更简单、可测 |
| DSH 官方实验插件 | 顶部持久横幅提示「非真实环境」的惯例 | — |

## 方案

**分层**：新增纯数据层 `src/client/demo.ts`（无副作用、可单测），面板只在 RPC 调用入口包一层。

### 1. `src/client/demo.ts`（新文件）

导出三样东西：

- `DEMO_DATA`：六个页面需要的完整夹具（`DayPayload` / `MinutesPayload` / `MinutesOverview` / `MinutesRangeDTO` / `BackgroundsPayload` / `{jobs: JobDTO[]}` / `AsrStatusDTO` / `AsrModelsPayload` / `SpeakerPayload` / `SkillsPayload`）。固定日期 `2026-11-17`，4 位虚构说话人（张思齐 / 肖晓东 / 龙嘉奇 / 未识别），转写 12 条，覆盖「有名字 / 未识别 / 系统轨 / 麦克风轨」四种形态。
- `demoResponse(op, payload)`：命中夹具的读操作返回 `{ok:true, value}`；写操作返回 `{ok:true, value:<最小可渲染结果>}` 且**不产生副作用**；未列出的 op 返回 `null`，调用方回退到真实 RPC。
- `isDemoOp(op)` / `isDemoWrite(op)`：供面板显示「演示模式下不可用」时使用。

**为什么放客户端而不是宿主**：演示只针对页面。放到宿主就要在每条路由判断开关，还要防止演示态被写进真实 JSON——风险面大得多。客户端拦截天然不碰文件。

### 2. `src/client/panel.tsx`

- `rpc()` 早已是全局面板入口，在它内部加一层：
  ```ts
  const demo = demoResponse(op, payload)
  if (demo) return demo
  ```
  这样 30 多个调用点都不用改。
- 新增 `const [demoMode, setDemoMode] = useState(readDemoFlag())`，`useEffect` 写回 `localStorage['dsh-mm-demo']`。
- 演示模式下，数据加载后 `setData/setMinutes/...` 直接拿到夹具，无需额外分支。
- 顶部横幅：`演示模式 · 示例数据` + 「退出演示」按钮，样式复用现有 notices 的行内条。

### 3. 关于页开关

在 `renderAbout()` 里加一个卡片：说明 + 开关按钮（进入 / 退出），并提示「演示数据不会保存」。

### 4. 写操作的处理

演示模式下这些 op 走 `demoResponse` 的空实现，界面表现为「看起来保存成功」但不落盘：

`minutes.upsert` `minutes.delete` `minutes.clear` `minutes.generate` `jobs.start` `jobs.cancel` `jobs.clear` `backgrounds.save` `backgrounds.delete` `speaker.add` `speaker.delete` `speaker.enrollRecent` `asr.set` `models.select` `models.remove` `models.add` `update.apply`

**为什么不直接禁用按钮**：演示时要能演示交互流程（点保存、看列表变化）。空实现既安全又能演。

## 被否决的方案（Rationale & Alternatives）

1. **宿主侧返回假数据**：要在每条 RPC 前面判断开关，且必须逐条保证不写文件；漏一个就会把演示数据写进真实纪要。客户端拦截做不到「不小心写文件」，风险结构上更低。
2. **单独做一个演示页面**：用户要求的是「这几个页面都用 mock 数据」，另起页面等于维护两套 UI，演示时看到的也不是真实界面。
3. **什么都不做，演示时手动造数据**：现状就是这样，问题是造完要清理、且容易漏删。
4. **把假数据放到手机端也生效**：本次非目标，手机页面走服务端渲染，接入方式不同，留待后续 spec。

## 代价与风险（Drawbacks & Risks）

| 风险 | 验证 | 回退 |
| --- | --- | --- |
| 演示模式下误以为在操作真实数据 | 顶部横幅常驻 + 关于页按钮文案明确 | 横幅一直显示，退出即恢复 |
| 夹具字段与真实 DTO 漂移（改了类型忘了改夹具） | `npm run check:client` 的渲染冒烟 + 逐页临时切换默认标签渲染 | 夹具写在同一文件，编译期类型对齐 |
| 面板某些分支拿到空数组导致空白页 | 冒烟渲染六个标签，确认每页有内容 | 逐步补夹具字段 |
| localStorage 不可用（隐私模式） | `try/catch` 包裹，退回默认关闭 | — |
