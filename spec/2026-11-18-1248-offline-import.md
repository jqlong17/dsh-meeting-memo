# 离线导入：把已有的录音文件转成可回看、可生成纪要的独立任务

> **Status**：Proposed
> **起始日期**：2026-11-18
> **预估工时**：240–320 分钟（原生转写 90 / 存储与 RPC 60 / 新 tab 与复用组件 90 / 测试与验证 40）
> **对应提交**：（实现后回填）

## 背景 / 问题

现在这个插件只能转写**它自己录到的声音**：采集进程把麦克风与系统音实时切成句子，写进 `asr-log/<day>/snippets.jsonl`。手上已有的录音——手机录的、别的会议软件导出的 m4a、一段采访——完全进不来。

想把这些音频塞进「今日」页是危险的：

- **时间戳会重叠**：`snippets.jsonl` 是纯追加的时间序列，同一分钟已经有现场片段时，再追加一套就是双份密度、双份文本，生成纪要会把内容写两遍。
- **删改动不得**：说话人归属、打标、声纹旁挂文件全部按**行号**对齐（`speaker-assignments/<day>.json`、`speaker-labels.json` 的 `lines`、`emb.jsonl` 的 `line`）。要“替换某段”就得重排行号，三处引用必须同时改写，漏一处就把名字挂到别人身上——这个坑踩过一次。
- **声纹会污染**：导入音频是另一套设备（手机、录音笔），把它的声纹混进现场质心会让实时识别掉分。

所以不是“加个上传按钮”的事，而是**这批数据该不该进那一天的数据集**。

## 目标与非目标

**目标**

1. 新增一个标签页 **离线导入**（放在「说话人识别」之后），与「今日」的实时数据**完全隔离**。
2. 支持选择本地音频文件（m4a / mp3 / wav / mp4 的音轨），在本机用**现有模型**转写，不引入第二套推理栈。
3. 每个导入任务有**自己的时间轴**，横轴从 `0:00` 开始（文件内相对时间），不是真实时钟。
4. 时间轴、选区、转写列表、复制等交互**复用现有组件**；**不再区分麦克风/系统**，导入音频一律单轨。
5. 导入后可以**直接复用现有的 AI 生成纪要链路**，纪要与转写一起存在该任务目录下。
6. 导入过程走**任务队列**：可见进度、可取消、失败有原因。
7. 同一文件重复导入被拦下（按内容哈希）。
8. 「今日」「纪要」「说话人识别」的数据与行号**零变化**。

**非目标（这次不做）**

- 不做导入任务的说话人识别（导入音频是另一套设备，要认人得重新登记声纹；先只出文本）。
- **不把导入结果并入某一天的纪要**。纪要按「时间线」这一维度保存，导入音频属于另一条时间线（文件内 0:00 起），混进 `minutes/<day>.json` 就破坏了隔离。导入任务的纪要只存在于自己的目录里。
- 不保留源音频副本：转写完成即只保留文本，插件不复制原文件。
- 不做云端上传、不做第三方 ASR 兜底。
- 不支持视频画面，只取音轨。
- 不做断点续传：中断后重来（v1 可接受）。

## 方案

### 1. 存储：独立命名空间

```
~/.dsh/meeting-memo/imports/<id>/
  meta.json        任务元信息（见下）
  snippets.jsonl   转写片段（相对时间，单轨）
  minutes.json     生成的纪要（如果生成）
  minutes.md
```

**目录里没有音频**：转写直接读用户选中的原文件，完成后不再需要它；插件不复制、不缓存音频，删除任务只删这几个文本文件。

`id` 形如 `20261118-1240-a1b2c3d4`（时间前缀便于排序 + 内容哈希前 8 位便于去重）。

```json
// meta.json
{
  "version": 1,
  "id": "20261118-1240-a1b2c3d4",
  "name": "采访录音.m4a",
  "size": 52428800,
  "hash": "a1b2c3d4…",
  "durationSec": 3725.4,
  "createdAt": "2026-11-18T04:40:00.000Z",
  "status": "done",
  "model": "SenseVoiceSmall_int8",
  "truncated": false
}
```

```json
// snippets.jsonl：一行一句，时间是相对文件的秒数
{"startSec":12.4,"endSec":15.1,"text":"……"}
```

**不写 `line` 字段之外的引用**：导入任务内部也用行号，但只在本任务内使用，与 `speaker-assignments`、`speaker-labels` 无任何耦合。

### 2. 原生侧：新增 `transcribe` 子命令

```
asr-helper transcribe <file> [--model DIR] [--engine file]
```

- 用 `AVAudioFile` 流式读（每秒 16k 单声道），**不整体载入内存**；超过 1 小时的文件也必须能跑。
- 复用现有 VAD 切句与 SenseVoice 推理；输出事件：
  - `{"type":"snippet","startSec":…,"endSec":…,"text":…}`（相对秒）
  - `{"type":"progress","processedSec":…,"durationSec":…}`
  - `{"type":"done","snippets":N}`
- 块内不区分 mic/system；`track` 固定为 `import`。
- 读不出音轨/格式不支持时立刻报错退出，错误信息落在任务上。

### 3. 插件侧：RPC 与 job

| 操作 | 作用 |
| --- | --- |
| `imports.list` | 列出任务（id、文件名、时长、状态、创建时间、片段数） |
| `imports.start` | 入参 `{path}`：算哈希 → 查重 → 建目录 → 建 job → 起 `transcribe` |
| `imports.get` | 入参 `{id, range?}`：返回该任务的时间轴桶、片段列表、meta |
| `imports.cancel` | 取消正在跑的转写（子进程 SIGKILL，任务标 `cancelled`） |
| `imports.delete` | 删除任务目录（仅当不在运行） |
| `imports.generate` | 用现有生成链路，把选中区间整理成纪要，写入该任务目录 |

job 类型新增 `import`，进度为 `processedSec / durationSec`；失败时把 stderr 摘要写进 job 的 `error`。

### 4. 前端：新增「离线导入」标签

位置：`今日 / 纪要 / 背景 / 任务 / 转写服务 / 说话人识别 / **离线导入** / 关于`

页面结构：

```
[导入音频]  ← 选择文件，弹系统文件选择器
──────────────────────────────────────────
任务列表（最近在前）
  采访录音.m4a   1:02:05   ✓ 已完成   183 句   [查看] [删除]
  会议副本.m4a   0:41:12   ⏳ 转写中 62%        [取消]
──────────────────────────────────────────
（选中某个任务后，下方显示）
  标题：采访录音.m4a · 1:02:05
  [时间轴：0:00 ────────────── 1:02:05，可拖动框选]
  [0:12] ……            ← 转写列表，单轨、无麦克风/系统筛选
  [0:15] ……
  [AI 生成纪要]
```

- 时间轴复用现有组件，刻度改为 `0:00 / 0:15 / 0:30 …`（或按小时切分）。
- 选区、复制、勾选行为与今日页一致。
- 「AI 生成纪要」复用现有生成链路；生成结果渲染成 Markdown，落 `imports/<id>/minutes.md`。
- 任务运行中每 2 秒刷新进度（与现有 job 轮询合并）。

### 5. 界面结构与纪要落点

「离线导入」是**自包含**的：导入任务、转写结果、纪要结果全部在这一页里闭环，不往「纪要」页写任何东西。

```
[导入音频]
┌ 任务列表 ─────────────────────────────┐
│ 采访录音.m4a   1:02:05  ✓ 183 句  [×] │
│ 会议副本.m4a   0:41:12  ⏳ 62%    [×] │
└───────────────────────────────────────┘
选中一个任务后，下方出现：
  [转写] [纪要]              ← 两段切换
  ├ 转写：时间轴（0:00–时长）+ 片段列表（单轨）
  └ 纪要：[AI 生成纪要] → Markdown 正文 + [复制] [重新生成]
```

- **任务列表**常驻上方，点击切换选中任务；运行中的任务显示进度条。
- **转写 / 纪要** 用分段控件切换，默认停在「转写」，生成完成后自动切到「纪要」。
- 纪要**只落在** `imports/<id>/minutes.json` 与 `minutes.md`，页面上用 Markdown 渲染，不进入 `minutes/<day>.json`，也不出现在「纪要」标签里。
- 删除任务时连同 `minutes.*` 一起删，磁盘上不留孤儿文件。

## 被否决的方案（Rationale & Alternatives）

| 方案 | 否决理由 |
| --- | --- |
| 把导入片段写进 `asr-log/<day>/snippets.jsonl` | 时间戳重叠 → 密度与转写双份；要消重就得删改，而行号是全系统的身份键，删改等于把说话人归属和打标全部打乱 |
| 导入时“替换该区间已有片段” | 需要重排行号并同步重写 `speaker-assignments`、`speaker-labels`、`emb.jsonl`，事务性要求高，出错代价是名字挂错人 |
| 在「今日」页加一个导入按钮，导入后落当天 | 入口顺手，但数据仍在同一天，冲突问题只是被隐藏；高频误用后很难回滚 |
| 单独起一套 Python 转写脚本 | 与现有 SenseVoice/声纹模型重复，多一套依赖和模型加载路径 |
| 导入时识别说话人 | 声纹按设备分组，导入音频是另一套设备，混入会拉低现场识别；先只出文本 |
| 用真实时钟对齐时间轴 | 需要用户填日期+起点，且与已有录音必然产生重叠判断；相对时间 0 起点既简单又无冲突 |

## 代价与风险（Drawbacks & Risks）

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 长文件占用磁盘（1 小时 m4a ≈ 30–60 MB） | 累积 | 导入目录纳入「保存内容」的占用统计；支持删除任务 |
| 转写耗时（1 小时音频约 1–3 分钟） | 等待 | 走任务队列，可离开页面；进度可见；可取消 |
| `AVAudioFile` 对某些容器（如带 DRM 的 m4a、变速音频）读不出 | 导入失败 | 立刻失败并给出明确原因，不留半成品目录 |
| 大文件哈希计算耗时 | 选完文件后卡顿 | 流式读 + 只取前 8MB 与文件大小/时长组合做指纹（v1 允许碰撞风险） |
| 导入任务多了以后列表变长 | 体验 | 按创建时间倒序，默认只展示最近 20 个 |
| 新增一个 tab 挤压导航宽度 | 界面 | 现有标签已是横向滚动，实测 8 个标签仍可放下 |

## 已定结论（Decisions）

| 问题 | 结论 |
| --- | --- |
| 是否并入某天纪要 | **不并入**。纪要按时间线维度保存，导入是另一条时间线，必须隔离；导入的纪要只存在于任务目录 |
| 是否保留源音频 | **不保留**。转写在原文件上直接进行，完成后只留文本；插件不复制、不缓存音频，删任务不涉及音频 |
| 用哪个模型 | 跟随「转写服务」当前选中的模型，不单独配置 |
| 多轨道音频 | 一律下混为单声道 |

## 测试计划（先红后绿）

1. **存储**：`imports.start` 建目录后 `snippets.jsonl` 行号从 1 递增；`imports.delete` 后目录消失。
2. **去重**：同一文件第二次导入返回“已存在”，不新建目录。
3. **隔离**：导入完成后 `asr-log/<day>/` 下所有文件 mtime 不变（用真实目录断言）。
4. **原生转写**：用一个 10 秒的测试音频跑 `transcribe`，断言输出片段数与 `done` 事件；用 65 秒音频断言 `progress` 至少两次。
5. **取消**：转写中 `imports.cancel` 后进程消失、任务状态为 `cancelled`、不留半成品 `minutes.json`。
6. **生成纪要**：导入任务调用生成链路，产物落在 `imports/<id>/minutes.md`，`minutes/<day>.json` 不变。
7. **前端冒烟**：新 tab 在无任务、有任务、转写中三种状态下都能渲染；「转写/纪要」两段可切换。
8. **隔离（纪要）**：导入任务生成纪要后，`minutes/<day>.json` 不变，且「纪要」标签的列表条数不变。
9. **不留音频**：导入完成后 `imports/<id>/` 下没有 `*.wav|*.m4a|*.mp3`，任务目录只有 meta/snippets/minutes。
